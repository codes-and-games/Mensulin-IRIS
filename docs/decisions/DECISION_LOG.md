# Decision log (preparation phase, 2026-10-07)

Each entry: **Decision**, alternatives, reason/scientific justification, consequence, reversible?

**D-01 Dataset roles are set by scientific fit, not size.** Alternatives: pool every dataset; use the largest. Chosen: HUPA-UCM and BrisT1D-Open for pipeline and 24 h method checks only (no cycle labels, about 2 weeks per person); DiaTrend for long-series negative control and ISF/TDD; T1DEXI as the only route to cycle-labelled analysis; OhioT1DM optional. Reason: a cycle-skill claim needs labels and enough cycles per person; none of the open datasets has either. Consequence: Phase 1 makes no cycle-skill claim. Reversible: yes, if labelled data is obtained.
**D-02 No cycle labels are inferred or manufactured.** Alternatives: infer phase from temperature/TDD periodicity or calendar. Reason: circularity (the quantity to be estimated would define the label) and the project document forbids it. Consequence: M2/M3 are `NOT YET JUSTIFIED`. Reversible: n/a.
**D-03 ML stays a small benchmark with fixed hyperparameters.** Alternatives: tuned GBMs, deep models, hyperparameter search. Reason: IRIS's question is physical/biological and its estimator is a state-space model; tuning adds leakage and false-performance risk with no gain for the research question. Consequence: nothing to "train" on Kaggle now; Kaggle is an optional independent repeat. Reversible: yes.
**D-04 S1 and S2 remain TEST-mode code-verification experiments.** Alternatives: relabel their synthetic lineage as ASSUMPTION so they pass the production gate. Reason: it would present synthetic-truth recovery as production evidence. Consequence: they are reported as verification, never as evidence; "SCIENTIFICALLY REFUSED" in production is correct. Reversible: yes (a gate change needs owner approval).
**D-05 Verified values reach the production gate through `sync_population_status`, never by hand-editing the YAML.** Alternatives: manual edit; make the gate read the CSV. Reason: the gate reads `status` from the population YAML while sign-off is recorded in the CSV; a one-way, value-checked bridge removes silent drift. Consequence: S3 runs once nine named S1 rows are RESOLVED and synced (tested in a scratch simulation). Reversible: yes.
**D-06 Dataset id `brist1d` and raw folder `data/raw/brist1d`.** The empty placeholder `data/raw/bristol` was renamed because M6's config and the loader use `brist1d`; mismatch would break `register_raw` pairing. Reversible: yes.
**D-07 Grid-consistency guard in `load_events`.** Alternative: trust the config. Reason: an ingested 15-minute grid with a configured 5-minute experiment would silently mis-scale coverage and the EKF time step. Consequence: a clear blocker instead of wrong numbers. Reversible: yes.
**D-08 The readiness matrix is generated** (status and blockers from a live production run, expected outputs from each experiment's file; judgement columns authored). Reason: a hand-written matrix drifts. Reversible: yes.
**D-09 Hossmann evidence is recorded as prepared evidence, not as verification.** The primary page was inaccessible to automated retrieval, so no page/table numbers were recorded. A possible mismatch (+2.7% CrI 0.4-5.0 in the 84.7% sentence vs IRIS +0.026 CI 0.003-0.050) is flagged for the human reader. Consequence: S1 stays unverified until signed off. Reversible: n/a.
**D-10 Pre-registration thresholds.** C1 (`hp > 1`) and C2 (`excess_tci > 0`) are null boundaries, so freezing them is not tuning; `threshold_units: 2.0` is a grid placeholder and needs the owner's written justification (or the full grid reported). Reversible: before freeze only.
**D-11 Freeze timing:** after S1 and L2 are known, before any production F1-F6/R/E1 run, marked by tag `prereg-v1`. Reason: confirmatory status requires thresholds fixed before results are seen. Reversible: no (amendments allowed, but then exploratory).
**D-12 The E1/E2 production reader is deferred** (code limitation), and the climate branch is Phase 1b/optional. Alternatives: write it now. Reason: the file format and location rule are not yet frozen/seen, so any reader would be guesswork; the core claim (potency, population, fusion, robustness) uses parametric scenarios and does not need it; S5 stays `blocked` and reported as such. Reversible: yes.
**D-13 Production runs must be made from a committed Git tree.** The tarball had no `.git`; run ids then read `nogit`. A dirty tree is marked in the run id. Consequence: `git init`, commit and tag before any production run (setup guide). Reversible: n/a.
**D-14 Controlled-access data never leaves its approved environment** (no Git, no Kaggle, T1DEXI analysed inside Vivli). Reason: DUA terms and re-identification risk.
**D-15 Second reader preferred for parameter verification;** a single reader is allowed only with `--allow-single-reader`, recorded in the log as a limitation.
**D-16 The repository contains 27 experiments, not 26** (M6_circadian_recovery was not counted in the brief). All 27 are in the matrix.
**D-17 DiaTrend multi-sheet Excel layout** may need a small preprocessing step after the real audit (conditional code limitation); not written blind.
**D-18 Open decision 0001 resolved: option B** (keep the four design parameters as declared ASSUMPTIONs and sweep them in R2). Alternative: pick values by authority. Reason: no primary source exists; sweeping exposes the dependence. Reversible.
**D-19 Open decision 0002 resolved in principle: option B is the target design, implementation pending (task T-01).** Alternative A (keep `coupled` everywhere). Reason: conflating epistemic kinetic uncertainty with between-person variation would inflate heterogeneity for deterministic scenarios, which bears directly on conclusion C1. Consequence: until T-01 is done, F5/F6/R* results for deterministic scenarios are conditional and not confirmatory; C1/C2 should be evaluated on stochastic scenarios (S6, S7, and S5 if the climate branch is completed). **This is the one open technical task that affects the confirmatory claim.** Reversible.
**D-20 Open decision 0003 confirmed as written.** Reversible.
